## Repository Command Center remediation

Fixes the remote projection path so GitHub provider failures are diagnostic rather than empty states, and turns the existing Command Center sections into dense, project-scoped operational surfaces.

### Fixed integration defects

- GitHub Actions definitions and repository-wide runs are synchronized separately with pagination, workflow trigger metadata, per-run jobs/steps/artifacts, failure actions, and typed diagnostics.
- GitHub JSON is no longer corrupted by URL credential redaction when a later JSON field contains an email address.
- Pull-request summary sync avoids GitHub CLI GraphQL node-budget exhaustion; selected PRs load bounded rich detail (files, commits, checks, reviews, and inline comments) on demand.
- Raw GitHub REST and CLI field names are normalized at the projection boundary instead of being discarded by the frontend.
- Each remote category persists healthy/stale/failed state, safe reason, required permission, recovery action, and last successful sync.

### Product and safety work

- Reworked Overview, clean Changes state, Branches/worktrees, Actions, PR cockpit, Issues, Releases, and Security to use real project data and explicit diagnostics.
- Added schema 14 migration for durable sync diagnostics and updated release metadata.
- Kept GitHub credentials in the existing `gh` secure-store path; no token is persisted or sent to the frontend.
- Fixed a multibyte PTY output-tail panic found while exercising workspace restoration.
